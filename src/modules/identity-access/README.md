## Entrada candidata
O bootstrap seleciona o piloto se VITE_SAGB_IAM_PILOT=true ou a URL aponta para o ref LOZE. Não configure antes do gate. A tela candidata usa SDK existente, chave pública, sessão separada, PKCE (mesma aba), admissão IAM e allowlist de rede do cliente. Não monta o App legado nem registra módulo no menu. Após autorização, mostra confirmação, não dashboard. Nenhuma rota de domínio ou função administrativa foi liberada. RLS/backend e revisão de funções serverless são obrigatórios antes do cutover. Requer redirect exato /auth/reset-password autorizado. Se o código não estiver na mesma aba com o verificador, solicitar novo link. Testes de contrato não comprovam Auth real.

## Primeiro acesso controlado
A tela usa Auth signInWithOtp (link ou código conforme configuração do Auth) e PKCE para /auth/first-access. O banco deve possuir a RPC sagb.iam_claim_first_access e uma autorização única com validade para o endereço autorizado, sem expor catálogo de e-mails. Exige sessão real recente de email OTP/magiclink, identidade confirmada sem senha anterior/telefone/outra identidade, vínculo exclusivamente sagb-entry. Sem reativação automática de vínculos revogados. Após admissão, usuário define senha na tela. Cadastro Auth pode criar identidade no projeto compartilhado, mas sem autorização SagB para outros endereços; não alterar signup/Auth global. Redirect permitido e entrega de e-mail ainda precisam confirmação. VITE_SAGB_IAM_URL + VITE_SAGB_IAM_PUBLIC_KEY opcionais exclusivamente no Preview; nunca service role. Não usar App legado no novo ref. Se conta pré-existente com senha, usar fluxo de provisionamento aprovado, não redefinir automaticamente.
